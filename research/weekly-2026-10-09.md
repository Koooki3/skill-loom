# Skill Loom v0.1.1: receipt validation regression report

9 October 2026 · engineering supplement to the version 0.1 systems report.
This is a deterministic software regression study, not a peer-reviewed paper or
an agent task-quality experiment. The original manuscript, PDF and twelve-case
study remain historical artifacts of v0.1.0; this report records the patch.

## Problem and observed baseline

Routine maintenance prompted an inspection of failure-reporting boundaries.
A newly constructed receipt containing the valid JSON value `[]` reproduced an
uncaught `AttributeError` in both the CLI and the opt-in Stop-hook script.
Both exited 1 without the hook's promised unverified-acceptance message. This is
a development-discovered input-contract bug, not an incident attributed to a
user skill or a model. Raw local traces and paths remain private.

## Change and acceptance contract

Validate the top-level receipt object, optional profile type, list/object
collections, unique nonempty string check IDs, artifact paths and hexadecimal
SHA-256 fields before reading artifact bytes. Invalid shapes raise `LoomError`:
the CLI emits structured JSON and exits 2; the hook emits an explicit unverified
message and exits 1. Existing valid receipts keep their pass/fail decisions.
No automatic repair loop, native hook installation or semantic verifier is added.
Artifact path resolution is unchanged; this patch is not a filesystem sandbox.

The six new regression tests cover nonobject receipts, malformed check shapes,
malformed artifacts, validation before artifact reads, valid/incomplete controls,
and the actual CLI/command-hook script entrypoints. The fixture matrix was chosen
during development; it is neither a held-out benchmark nor a statistical sample.

## Results and reproducibility

On the local Windows Python 3.12 environment, all six new tests passed. The full
suite ran 49 tests: 47 passed and two skipped (POSIX execute bits and unavailable
symlink privilege). The isolated offline demo passed exact rollback, reapplication
and no-change checks. Cross-platform patch CI is checked separately at release;
local results alone do not verify Linux, macOS or native host hook behavior.

```bash
python -m unittest discover -s tests -v
python scripts/check_release.py
python -m skillloom demo --workdir <new-isolated-directory>
```

## Research interpretation

[ClaimReceipt v1](https://arxiv.org/html/2609.01992v1), §2.1/§3.1/§6, motivates
keeping typed evidence, byte integrity, claim sufficiency and coverage distinct.
Our shape validation prevents undefined input handling; it cannot establish the
truth or sufficiency of declared evidence. We did not reproduce that paper,
implement its protocol or measure downstream model benefit. The next useful
step remains task-specific behavioral evaluation, not accumulating more checks.

No new global skill was installed. The actual user discovery root contained
39 skills with zero static errors/warnings. Structural observation covered one
explicit project conversation and does not attribute skill utility or task success.
The seven registered public sources were observed; one directory source changed.
A new upstream commit remains a review candidate until a concrete local need and
selected-content/license review justify adoption.
