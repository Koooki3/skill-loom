# Observation identity and conservative review coverage

Engineering research supplement for Skill Loom v0.2.0. Reviewed 16 October 2026.
This is a systems technical report, not a peer-reviewed study or a new learning algorithm.

## Abstract

Repeatedly importing evidence must not make a rarely needed skill appear better
observed than it was. Review of the new host-observation workflow found two
accounting failures in unreleased main: repeated input paths were counted as
different files, and aggregate reports with unknown overlap were added together.
We reproduce both failures, distinguish their counting units, and implement a
conservative policy. A twelve-case synthetic study changes from six contracts
met in the baseline to twelve in the candidate. This measures specified software
behavior, not task quality, confidence, cost savings, or generalization.

## Motivation and local evidence

The weekly read-only sample covered one explicitly selected project conversation
over the preceding week. Multiple task events in one file do not establish
multiple independent sessions or opportunities to use each installed skill.
Static inspection found 39 user-maintained skills, zero errors and zero warnings.
No global skill was added, removed or rewritten. Claude runtime was not sampled
this week; previous maintainer-reported Claude samples are not new independent
measurements.

The defect was found through source review and synthetic reproduction, not a
verified incident of incorrect real-world deactivation. Skill Loom proposes
human review and never deactivates a skill automatically.

## Prior work and design decisions

[R17, CloudEvents v1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md),
required id/source and Privacy and Security, provides scoped event identity.
We take the distinction between a resend and a new event, without imposing
CloudEvents on private host logs or exporting their identifiers.

[R18, PROV-DM](https://www.w3.org/TR/2013/REC-prov-dm-20130430/),
W3C Recommendation, 30 April 2013, sections 5.2 and 5.6, distinguishes
derivation from collection membership. A regenerated report is derived from
inputs; a new report name does not create new observations. We do not implement
PROV or claim conformance.

[R19, OpenTelemetry Metrics Data Model](https://opentelemetry.io/docs/specs/otel/metrics/data-model/),
Single-Writer, Temporality and Overlap, was read on 16 October 2026. Single-Writer
is Stable; Overlap is Development. The living document motivates explicit
overlap handling, not interpolation of skill usage. No reliable fixed release
was verified for this reading.

[R20, Ubbala, arXiv:2609.14017v1](https://arxiv.org/html/2609.14017v1),
12 September 2026, sections III–VII, separates event and logical-fact identities
and examines replay/order properties under source assumptions. Its results are
synthetic contract validation. We borrow test properties, not its revision
ordering or empirical results; host logs lack the required authoritative IDs
and revision contract. The paper was not reproduced.

These sources inform our engineering choices. None establishes the default
ten-file/seven-day review policy as a statistical confidence bound. A targeted
recent-paper search also screened
[event prediction across heterogeneous logs](https://arxiv.org/abs/2610.17503)
at metadata/abstract level only; it was excluded because prediction does not
resolve our identity or coverage contract. This was not an exhaustive review.

## Counting contract

| Unit | Implemented meaning | Remaining unknown |
|---|---|---|
| Input file | Distinct filesystem object within one observation command; resolved path fallback if inode identity is unavailable | Copied snapshots or separate files from one logical session |
| Per-skill sessions field | Legacy name for input files containing the recognized signal | Verified logical sessions, tasks and independent trials |
| Calls | Recognized recorded Skill calls for Claude; SKILL.md-read signals for Codex | Unique underlying events across copied files; success |
| Report | An aggregate with no exported source-member identities | Overlap with another report, including different dates |
| Span | Inclusive elapsed days between one report's date endpoints | Distinct observed days or continuous capture |

Observers resolve selected paths and use filesystem identity locally to skip
aliases, repeated paths and hardlinks. No path, inode or session ID is added to
the exported report. No whole-log content hash, new dependency or host hook is
required. Different files with identical contents remain different inputs;
within-file event replays and overlapping snapshots remain unresolved.

For a host's reports R and policy F/D, eligibility is:

    eligible(R) = any(files(r) >= F and span(r) >= D for r in R)

Separate reports cannot supply the two thresholds independently. The output
observed_files and span_days are their respective maxima; they need not come
from the same report. Eligibility is computed per report, never from those two
display maxima. Per-skill calls and sessions are maxima across reports, not a
deduplicated union. A positive signal in any report prevents an unobserved
candidate, including signals from reports too small to qualify on their own.
reports_supplied and qualifying_reports count supplied aggregates, not unique
sessions.

This deliberately undercounts genuinely disjoint aggregate reports. To combine
known inputs, regenerate one observation with all explicitly selected files.
Legacy reports remain readable, but old file_count may already contain repeated
paths; regenerate them before relying on review eligibility. The legacy CLI
flag --min-sessions and Python keyword min_sessions remain supported;
--min-files names the actual unit.

## Executed study

The comparator is unreleased main
f3e654ebb25377ed027bdf9aeae4c8edd62c7938, not v0.1.1, which did not have usage.
The same script imports either reviewed source tree into a fresh process and
uses temporary synthetic inputs. There are six cases per host:

| Cases, each run for Claude and Codex | Baseline | Candidate |
|---|---|---|
| Single report below file threshold | Contract met | Contract met |
| Same six-file aggregate supplied twice | Premature candidate | No candidate |
| File and span thresholds met in different reports | Premature candidate | No candidate |
| One report meets both thresholds; one skill observed | Contract met | Contract met |
| Positive signal appears only in a small additional report | Contract met | Contract met |
| One input path supplied ten times | Premature candidate | No candidate |

These are development-selected examples, not held-out tasks or independent
statistical trials. The candidate also has unit tests for path aliases,
hardlinks, distinct copied files, non-spliced date endpoints, replay/order
invariance of decisions and counts, legacy inputs and CLI aliases.

[Machine-readable baseline and candidate](results/observation-coverage.json)
include source-file hashes. Reproduce with reviewed checkouts:

~~~bash
python scripts/benchmark_observation_coverage.py --source-root <baseline-checkout> --out <private-baseline.json>
python scripts/benchmark_observation_coverage.py --out <private-candidate.json>
python -m unittest discover -s tests -v
python scripts/check_release.py
python -m skillloom demo --workdir <new-isolated-directory>
~~~

The documented baseline study exits 1 because six contracts fail; the candidate
exits 0. Local Windows / Python 3.12.8 ran 89 tests: 87 passed, two skipped
(POSIX execute bits and unavailable symlink privilege). The isolated demo passed
exact rollback, reapplication and no-change checks. Release CI is verified on
its exact commit separately; local results do not establish other platforms.

## Independent release review

A read-only independent review covered both this weekly patch and the previously
unreleased runtime. Three further failures were reproduced with synthetic files:
Windows backslash SKILL.md references produced no signal; linked worktree Git
metadata lost the remote-only marker; unvalidated catalog source fields were
interpolated into a suggested shell command. The generated adversarial command
was inspected as text and never executed.

The fixes accept Windows/mixed separators, read gitdir/commondir metadata without
launching Git, and validate repository/path fields against staging constraints.
Structured stage_argv is authoritative. Shell-simple paths retain a template
with a quoted destination placeholder; other portable paths receive argv only.
Callers must replace the placeholder and pass arguments without a shell.
Six additional synthetic tests cover these interfaces; fresh review follows
the corrected snapshot. This is not a full hostile-catalog security audit.

## Update decisions and limits

Seven registered upstreams were queried successfully. Four heads matched their
pins; Anthropic skills, VoltAgent's index and K-Dense scientific skills differed.
The selected changes concerned API/workflow guidance, discovery links and an
upstream scanner report, respectively. No concrete local gap justified adopting
a new skill or changing a pin.
[Source observation and limited review](../catalog/source-observation-2026-10-16.json)
records the scope; scanner labels and index descriptions are unverified claims.

Native Codex/Claude hooks, current Claude discovery, macOS, logical-event
deduplication, continuous capture, multi-user operation, performance and model
benefits remain untested. The policy trusts the stated aggregate counts and
cannot detect forged reports. It is not an adversarial proof or a privacy
guarantee. Future work should obtain an explicit privacy-reviewed source-member
contract before adding disjoint reports; identifiers alone would still not
establish independent trials or skill usefulness.

The original manuscript, reading PDF and TeX retain their 6 October scope.
This supplement, source register, validation record and blog carry the new
engineering evidence. Standards and papers retain their own licenses; none is
redistributed as MIT source.
