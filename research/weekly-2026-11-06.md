# Weekly supplement: select an observation interval without inventing coverage

This 6 November 2026 supplement records a compatible v0.3.0 capability.
The historical manuscript/PDF/TeX retains its 6 October scope.

## Need and bounded local case

The prior weekly procedure maintained a successful inspection cursor, while the
public observers could only summarize entire files. A separate private script
performed the recurring interval selection. We move that operation into a
shared, tested optional CLI/Python interface rather than add a global skill.

A read-only sample after 30 October 00:57:08 UTC through 6 November 05:40:47 UTC
selected one Skill Loom conversation: 781 structural records, eight host start
events and eight completion events. These events do not establish eight accepted
tasks. Static inventory found 39 user-maintained skills, zero errors and zero
warnings. The seven-calendar-day sample remains one input file and insufficient
for a deactivation review. Earlier samples share this conversation and are not
independent trials. Causal outcomes and interval token cost remain unknown.

## Implementation and preservation

Both observers accept optional --since (exclusive) and --until (inclusive).
Aware timestamps are compared as UTC instants; missing or invalid timestamps are
counted and skipped in filtered mode. No options preserve the old full-file
behavior and output shape. No model call, native hook, dependency or background
collector is added. Schema remains 1 with optional record_selection metadata.

Filtered file_count counts only files with matching timestamped objects. This
prevents empty selected files from inflating usage coverage. Codex cumulative
token totals remain null in filtered mode: a cumulative host counter does not
measure interval cost. The observer still scans all bytes and does not freeze
a growing file. Source-object deduplication remains local to one command;
copied records and overlapping time ranges are not logically deduplicated.

The [user guide](../docs/observation-windows.md) and two synthetic JSONL examples
define the commands, errors, downgrade and unresolved measurement limits.
Seven new unit-test methods cover both host parsers, CLI propagation, time zones,
boundary partitioning, missing timestamps, empty-file coverage, malformed input,
token scope and preservation. These are designed software contracts, not a
held-out behavioral benchmark.

## Theory and source choices

SkillScriptBench separates package behavior, documented invocations and
preservation of already-correct behavior [1]. We apply that testing distinction
to this change; we do not implement its AST method or reproduce benchmark gains.
Its tasks use constructed faults and do not establish reliability in long
downstream workflows.

The author's runtime-observability discussion separates evidence of occurrence,
attribution and outcome [2]. We use that distinction to preserve unknown cost
and task quality when selecting timestamps. This living blog and its reported
experiments were not independently replicated. Python's official aware datetime
contract supports comparison of instants; it supplies no capture guarantee.

Seven registered upstream heads were rechecked; two changed. VoltAgent adds
README discovery edits; K-Dense changes scanner reports. Comparison commit
metadata was complete, content review scoped, and scanner claims unvalidated.
The [source observation](../catalog/source-observation-2026-11-06.json) records
exact commits and limits. All installation pins are retained; no linked code,
scanner result or binary package is adopted. Official host release notes were
also checked; no host policy or runtime was updated.

We defer persistent collectors, automatic cursor storage, model judges, and token
delta inference. The new feature selects explicitly provided records; it does
not expand permission to observe unrelated tasks.

## Evidence and remaining limits

The [validation record](../docs/validation.md) records completed local checks;
publication requires successful CI for the same full commit before tag and Release creation.
Real input stays private; all public JSONL examples and added tests are synthetic.
Native Claude execution, native hooks, macOS, live-file snapshot consistency,
task-quality benefits, cost savings and continuous capture remain unverified.
No global skill changes or cache deletion occurred.
