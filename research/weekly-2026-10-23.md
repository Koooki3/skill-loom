# Weekly supplement: interpret path signals conservatively

Weekly run initiated 23 October 2026; release preparation resumed and sources
rechecked on 25 October. This note supplements the
[16 October study](weekly-2026-10-16.md). The original manuscript, PDF and TeX
retain their 6 October scope; this is an engineering report, not a new
model-performance experiment.

## Local evidence and problem

A private, read-only sample covered the interval after 16 October 06:19:28 UTC
through 23 October 04:08:35 UTC. One explicitly selected project conversation
contained 1,575 matching structural records. The user-level inventory contained
39 skills with no static errors or warnings. The observation window covered
eight calendar days but only one input file, so the default usage threshold
was not satisfied and no deactivation review was proposed. The earlier sample
was retained separately; neither sample represents all local activity.

Inspection found that embedded synthetic test code produced skill-name matches.
The observer searches serialized tool payloads; it does not check whether the
referenced file exists or whether the command ran successfully. The previous
description, “commands that open a SKILL.md,” therefore overstated the signal.
This is a curated real-case summary; raw records and machine identities remain
private. Task outcomes and causal skill value remain unknown.

## Compatible correction

The observer now emits optional schema-1 metadata
`skill_signal_basis: syntactic-tool-payload-path-reference`. Legacy
`skill_md_reads`, counts and the usage status `load-signal` remain unchanged.
Limits explicitly cover quoted code and failed commands. A synthetic regression
writes a transcript containing a quoted fixture path without creating a skill
or executing its command. It checks the weaker label and compatibility behavior.

We retained conservative positive-signal handling rather than guessing which
shell fragments performed real reads. Absence still cannot justify deletion.
A future verified-access signal would require an explicit host event contract
and its own validation; a shell parser is outside this correction.

## Research and decisions

HABIT-Bench v2 separates historical evidence from justified personalization,
including unaccepted suggestions and changes in scope. Its histories are
synthetic, and evidence access is not equivalent to supported decisions [1].
Our engineering inference is to keep user profiles explicit and task value
unknown when runtime attribution is missing; no habit-inference service is added.

MetaSkill v1 formalizes dependencies and text handoffs between selected skills.
It studies composition after selection and does not establish discovery quality
in an evolving library [2]. We retain explicit handoffs and gates, but defer a
new DAG runtime without a demonstrated local orchestration failure. Its artifact
results were not reproduced or transferred to Skill Loom.

PROV-DM membership can describe known members without claiming an exhaustive
collection [3]. This reinforces the existing distinction between listing inputs
and proving complete capture. No source-member schema is introduced here.

## Sources and verification scope

[Seven registered sources](../catalog/source-observation-2026-10-25.json)
were rechecked. Two heads changed since the previous observation: the VoltAgent
discovery index and K-Dense scanner reports. Selected content review found no
new local requirement warranting an installation. Index descriptions and scanner
findings remain unvalidated upstream claims. Registry pins and dependencies stay
unchanged.

The new case plus existing suite ran on local Windows/Python 3.12: 90 tests,
88 passed and two platform skips. The isolated demo passed installation, exact
rollback, reapplication and no-change checks. See [validation](../docs/validation.md)
for the dated release checks. These are software-contract results. Native host
hooks, macOS, model-task benefit, logical-session identity, continuous capture and
multi-user personalization remain unverified. Private recovery evidence is
retained; no global skills were changed.
