# 本地环境与产出管理

把运行入口、开发仓库、工作缓存和证据记录分开，能降低技能扫描成本，也能减少误删。目录约定是团队选择，不是对其它用户硬编码的绝对路径。

```text
<workspace>/
  projects/skill-loom/        # 可发布源码、文档、固定公开示例
  skills/<name>/             # 用户维护的运行文件，可由宿主入口链接
  cache/<task-id>/           # 明确可重建的下载、渲染与中间文件
  management/<change-id>/    # 私有计划、回退副本、验收记录
  outputs/<task-id>/         # 用户要保存、分享或交付的最终文件

<host-home>/
  skills or .agents/skills   # 按宿主实际规范确定的发现入口
  native runtime state      # 由宿主维护，不能纳入普通清理脚本
```

本机演练使用用户指定的 `D:/codex` 为工作根。移植时选择自己的根；不要移动 Codex/Claude home、登录状态、审批配置或数据库来“统一路径”。正在运行的宿主日志、SQLite/WAL、会话、插件缓存、浏览器数据及记忆均不属于普通项目缓存。

## 文件类型与保留策略

| 类型 | 例子 | 谁管理 | 可否清理 |
|---|---|---|---|
| 原始输入 | 课件、数据、源码、用户文档 | 用户/项目 | 默认保留，不用转换结果替代原件 |
| 最终产物 | 报告、图表、可编辑图源、提交包 | 任务负责人 | 明确交付位置和版本后保留 |
| 维护证据 | 固定来源、计划、备份、测试结果 | 维护者 | 设置留存期限，先验证恢复能力 |
| 可再生中间文件 | Python字节码、临时渲染、可重下下载 | 产生它的任务 | 依据归属、可再生性和使用状态精确清理 |
| 宿主管理状态 | 凭据、数据库、会话、插件版本 | 宿主产品 | 使用宿主自己的管理功能 |
| 未知历史目录 | 无owner、无说明、仍有消费者 | 待核查 | 不因“很旧”或“很大”就删除 |

建议在项目完成时更新 README 的入口、环境、实际测试和产物链接；接口/路径变化时同步对应文档；来源更新时更新来源记录；任务失败时记录失败范围。无需每次改文件都维护一份流水账。

项目根只保留下一位维护者需要的材料。第三方完整 checkout、压缩包、raw会话和临时截图进入私有缓存；可发布代码保留确定性生成脚本与必要小样本。最终图件旁保存数据和绘图脚本，避免只剩不可复现的 PNG。

## 可执行清理流程

CLI 只管理明确登记为可重建的单个任务缓存。采用已有目录前先人工盘点：是否只含本任务的派生文件？是否有原始文件、最终产物、活跃消费者或其它项目链接？确认后创建精确标记：

```json
{"owner":"skill-loom","reconstructible":true,"schema":1}
```

将该 JSON 保存为该任务缓存根下的 `.skillloom-cache.json`。不要在宿主 home、skills 根、整个 projects 根、最终 outputs 或备份根创建该标记。标记代表维护者已经判断归属，不是软件自动证明内容无价值。

```powershell
python -m skillloom cleanup-plan --root '<task-cache>' --age-days 14 --out '<private-state>/cleanup-plan.json'
# 阅读文件列表、总字节数和review_digest；停用该缓存的写入者。
python -m skillloom cleanup-apply --plan '<private-state>/cleanup-plan.json' --digest '<review_digest>' --receipt '<private-state>/cleanup-receipt.json'
```

仅删除计划中的精确文件，逐个复核字节和修改时间，不跟随链接，不使用递归删除。新出现的文件不在计划中；变化的文件使操作停止。每次删除前先写 pending_file，删除后更新已删除列表；中断时若仍有 pending_file，核对该精确路径是否存在，不能只按 deleted_files 推断没有删除。清理不提供文件恢复，故只适用于可重建缓存；有价值的源文件或证据应退役归档而非采用此命令。年龄只决定候选，不能证明归属。

Windows 自行处理目录时，始终在同一个 PowerShell 环境使用 `-LiteralPath`；递归移动/删除前验证解析后的绝对路径位于已授权根内。不要把 PowerShell 枚举结果再拼成 `cmd /c` 删除指令。

## 避免环境逐渐过时

维护环境清单需记录“检查时间”和“检查方式”：Python/Node/CLI实际版本、技能发现入口、链接目标、已验证工具和未验证依赖。依赖按任务需要在虚拟环境安装，不因 skill 提到工具就预装全部SDK。第三方服务凭据按宿主方式保管，绝不写入 skill、报告或公开仓库。

清理应服务于下一次运行：确认 README 中的命令仍可用、产物可重建、回退副本存在、技能入口没有指向已删除缓存，然后再清理可重建部分。不要声称“环境已完全精简”，应报告检查范围、实际删除字节、保留理由和未验证内容。
